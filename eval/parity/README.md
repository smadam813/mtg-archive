# Engine regression gate

Until cutover, this directory was the parity gate of spec §6.1: XMage against our goldfish engine on frozen decks. The gate passed on 2026-09-30 and the record is in `cutover/`. Since cutover the same tooling compares a candidate sidecar (a tag move, a patch, a shim change) against the XMage that serves floors. It runs on the host through `tools/EngineGate`, not in CI. Run it from the repository root.

1. `parity-baseline`, after cutover, after each pilot change, and after each accepted candidate. Pass `--image mtg-archive-xmage`: the image compose builds and serves floors from. The default `mtg-archive-xmage:ci` is a separate build and can be stale. It runs that image on every comparison at the base seed and the fresh seed and writes `baseline.json`. It writes nothing when more than 1% of a comparison's games end in an engine error.
2. `leak` and `determinism`, on each candidate before `parity`. Each appends one row per deck to `leak.md` or `determinism.md`.
3. `parity --image <candidate>`, which runs the candidate on every comparison and writes `report.md`.

`cases.json` holds the parity decks, the run count, the seeds, the horizon, the mulligan policies and the cases. The decks in `decks/` are frozen: the done-query decklists with each nonland our engine had no definition for swapped for a filler card of the same mana value (`filler.json` holds the rule and the cards), their rows and their card feature profiles. `baseline.json` checks each deck's hash. Each case runs under each mulligan policy; a case with a disruption profile runs paired, and each arm is its own comparison. A comparison passes when the 95% Newcombe interval of the difference (candidate minus baseline) contains 0; one that fails plays again at the fresh seed and fails only when it fails there too.

A case can name a `format` (`commander`, `brawl`, `competitive_brawl` or `standard_brawl`). The case plays under that format's game rules: start life, commander damage, the turn-1 draw and the free mulligans. A case with no format plays as Commander, the same default as a request. The baseline records the format, and a changed format makes the entry stale.

A case with a disruption profile can name a `disruption_mode` (`abstracted` or `interactive`). No mode is `abstracted`, the same default as a request. The baseline records the mode as the case wrote it, and a changed mode makes the entry stale. A mode with no profile, or an unknown mode, stops the gate when the cases load. An `interactive` case plays every event kind: the scripted opponent casts a real card for each (ADR 0013). A case can name a `play_policy` (`goal-aware-greedy` or `goal-aware-hold`, ADR 0014). No policy is `goal-aware-greedy`, the same default as a request. Both arms of a paired case play the policy. The baseline records the policy as the case wrote it, and a changed policy makes the entry stale. An unknown policy stops the gate when the cases load, and so does `goal-aware-hold` in a case that is not interactive. The determinism and leak gates play a disrupted case's row under its policy. The reader rejects any member that `cases.json` or `baseline.json` does not map, so the gate stops on a misspelt member instead of ignoring it.

A deck with its own `goal` (and optional `format`) is determinism-only. No case may name it, and parity never plays it. The determinism and leak gates play it under that goal and format. A parity deck plays in those gates under the first case of each game rules among its cases: one row each, named `<deck> (<format>)` when there is more than one. These rows play no disruption profile. Each case with a profile then adds one row, named for the case, that plays the disrupted arm: the case's goal, format and profile in its own mode. `brawl-seek-conjure` is a determinism-only deck. It plays in Brawl and holds Golos, every XMage seek card, and the XMage conjure cards. A seek card is a Mage.Sets card that calls `seekCard` at the pinned tag. `sources/` holds its decklist and the Scryfall records we froze it from. Those records went through the real ingest into a throwaway database, not the archive. If it fails a gate, fix the determinism patch; do not blank a card or drop the deck.

The Brawl decks come from the Brawl acceptance fixtures. `bq1-wrenn-and-six` (`../acceptance/brawl-query-1/`) plays under Brawl and under Competitive Brawl. `bq2-jolly-balloon-man` (`../acceptance/brawl-query-2/parity-deck.txt`) plays under Standard Brawl. Each case casts the commander by turn 3. `brawl-calibration` is Karn, Legacy Reforged, one Ornithopter, 58 Field Creeper and 40 Wastes. It has no tutor and no draw, so the goal (cast Ornithopter by turn 1) is met only when the kept hand holds Ornithopter. Its result has a closed form from the hand odds, the keep rule, the turn-1 draw (none on the play) and the free mulligans (one in Brawl, none in Competitive Brawl). These decks went through the real ingest into a throwaway database from the Scryfall records in `sources/`, with no filler swap.

The tier-4 cases guard interactive disruption on every tag move. `dq2-final-99-needle-t4-interactive` is the counter path: Needle on the battlefield by turn 4 under the default profile, in Commander, in interactive mode. Its deck, `dq2-final-99`, is the done-query 2 final 99 (`../acceptance/done-query-2/final-99.json`) with no filler swap, so it keeps its counterspells. It was frozen on 2026-10-11 from a copy of the archive, after the migration and a forced ingest there, so its card feature profiles carry the response features. `dq2-obeka` keeps its filler and holds no response card.

`bq1-wrenn-and-six-responses-t3-interactive-hold` runs the same case under `goal-aware-hold`. Its first baseline needs the owner's approval on the pull request.

`bq1-wrenn-and-six-responses-t3-interactive` is the protection path: Wrenn and Six on the battlefield by turn 3 through an Atomize at the end of turn 3, in Brawl, in interactive mode. Its deck, `bq1-wrenn-and-six-responses`, is a second freeze of the BQ1 decklist, made the same way and on the same day as `dq2-final-99`. It keeps Heroic Intervention, Snakeskin Veil and Veil of Summer as response cards, and Lightning Greaves and Swiftfoot Boots stop the Atomize from targeting. Its rows and profiles equal those of `bq1-wrenn-and-six`, apart from the archive ids, the `token_to_another_player` flag and the response features. The first freeze stays as it was, so its cases and their baselines do not change.

The gates start their own sidecar containers from `--image` (default `mtg-archive-xmage:ci`; build it with `docker build --target runtime -t mtg-archive-xmage:ci engine/xmage`). `--endpoint host:port` uses a running sidecar instead; determinism and leak take two different processes. For leak, a named first sidecar must run with the game-copies changes on and a named second one with them off; the gate cannot check either. A one-case `parity --only` run takes about 5 minutes at 10,000 pairs, so start it in the background. `parity --only <case>` prints its rows and leaves `report.md` as it is. `leak --only <deck|row>` and `determinism --only <deck|row>` play one deck or one row and leave `leak.md` and `determinism.md` as they are. `trace --case <name>` plays one case with every log kept and writes `diagnosis/<label>.json`. `EngineGate --help` lists every option.

## Accepted differences

`accepted.json` (beside `cases.json`) lists comparisons that fail on both seeds and are accepted. Each entry has four fields: `comparison` (a name from the report), `direction` (`lower` or `higher`: the candidate's floor against the baseline's), `cause` and `evidence` (a file under this directory, such as `diagnosis/<label>.md` beside the trace it explains). A comparison is accepted only when both seeds put the whole interval on the named side of 0. A missing file accepts nothing. The gate stops before any game when an entry names no comparison, names one twice, has a bad direction or an empty cause, or points at no file. The user approves each entry.

## The cutover record

`cutover/` holds the parity gate as it closed on 2026-09-30: `baseline.json` (our engine, `goldfish 1.0.0+f05e6f80`), `report.md` ("11 of 18 comparisons pass, 7 accepted"), `accepted.json` (directions `xmage_lower` and `xmage_higher`, against our engine) and `diagnosis/`. Nothing reads these files; they are the evidence of ADR 0011's transition.
