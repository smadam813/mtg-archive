# Embedding model freeze: qwen3-embedding:0.6b at 1024 dims

The retrieval eval (65 card queries, 13 rules queries, scored through the live service) settles M3's open model question. The gate rule — `qwen3-embedding:0.6b` must beat `nomic-embed-text` on overall nDCG@10 or the fallback wins — came out 0.289 vs 0.255 (recall@30 0.384 vs 0.357), so **qwen3-embedding:0.6b holds the model slot**. It also led on rules search (nDCG@10 0.781 vs 0.699), where nomic additionally refused two CR chunks (205.3, 608.2) as over its context length. Result files: `eval/retrieval/results/2026-08-30-*.json`.

**Oracle Tags stay in card documents.** An ablation pass (qwen3, tags stripped from document composition, full re-embed) scored below the tagged corpus on every card subset: overall 0.281 vs 0.289, archetype-vocab nDCG@10 0.087 vs 0.098, archetype recall@30 0.111 vs 0.126. Tags are a small consistent lift, not a backfire. Result file: `eval/retrieval/results/2026-08-30-qwen3-embedding-0.6b-no-tags.json` (recall@30 overall 0.375 vs the tagged 0.384). Both models still score badly on bare archetype queries ("stax", "voltron") — that gap is model-side, and closing it is re-ranking or fixture work, not document composition.

**The columns stay `vector(1024)`** (amendment to ADR 0001's embedding storage). A narrower model is zero-padded to the column width by `Embedding/OllamaEmbedder` — zero dimensions change neither dot products nor norms, so cosine distance is exactly the native-width distance, and queries pad identically. That policy is what made the nomic pass runnable without a migration, and it keeps the fallback runnable for future regression comparisons. `EmbeddingModel.Resolve` refuses only a model wider than the columns. `embedding_state` records the model's native width (768 for nomic).

**Schema freeze.** Downstream semantic-search work builds against the frozen tuple: model tag `qwen3-embedding:0.6b`, 1024 dims, prefix set `9D84B9513202418B`, card documents composed with oracle text verbatim (reminder text and symbols included) and Oracle Tags appended. The Retrieval eval is now regression-only: re-run it and commit the result on any change to a member of that tuple.

**Amendment (2026-08-30): the gate margin is not statistical signal.** A paired sign-flip permutation test (100k resamples) over the committed per-query results puts the overall nDCG@10 delta at +0.033, p = 0.11, and the card-search recall@30 delta at +0.001, p = 0.95; the archetype-subset reversal (p ≥ 0.09) and the tags-in-documents lift (p = 0.53) are likewise indistinguishable from zero at n = 78. The gate rule as written still selects `qwen3-embedding:0.6b` — it demanded a beat, not a significant one, and nomic's context-length refusals stand regardless — but this freeze records a tie broken by the gate's default, not a measured win. The card-search weakness is model-independent; closing it is fixture and retrieval work, and no re-run of the model comparison is owed.

**Card document composition stays verbatim** (amendment, 2026-09-19). Oracle text embeds as printed. Reminder text stays. Mana and tap symbols stay as symbols. The ablation tested two alternatives with the same model and the same eval, each on a full re-embed. Cell A removed parenthetical reminder text. Cell B removed it and wrote the symbols as words.

Neither cell beat verbatim on card search. The baseline is `eval/retrieval/results/2026-09-08-qwen3-embedding-0.6b.json`, the run each cell's result file names. nDCG@10: 0.496 verbatim, 0.472 cell A, 0.465 cell B. Recall@30: 0.425, 0.415, 0.417. Per query, cell A went up on 12 and down on 33; cell B went up on 17 and down on 37. Rules search did not change.

A second verbatim run, `eval/retrieval/results/2026-09-19-qwen3-embedding-0.6b.json`, measures the same frozen tuple after the re-embed that restored it. It scores 0.489 nDCG@10 and 0.425 recall@30, a gap of 0.007 to the baseline. Between the two verbatim runs, 24 of 65 queries moved, 12 up and 12 down. cs-012 gained a filter (+0.159). The rest is re-embed drift, largest on cs-025 (-0.226). That drift is the noise floor for this eval. Each cell loses more than it in aggregate, and each cell loses on about three queries for every one it wins.

Each cell fixed the case it targeted and lost a class of cards. Cell A removed the manifest-dread reminder text from cs-036's top 10, but the query's expected cards stayed outside the top 30 (+0.015 nDCG@10). It also pushed down every creature whose reminder text is its only functional wording: on cs-031, Glistener Elf moved from #96 to #7,271 and nDCG@10 fell 0.125. Cell B moved mana artifacts and one-mana creatures up by thousands of ranks. Sol Ring moved from #7,641 to #181, still outside the top 30. Other cards with "tap" text filled the top 10 (cs-008 -0.046, cs-043 -0.058). The unrelated cards that fill those queries' top 10 did not move under either cell. The next change to try is a facet or a re-ranker, not composition.

Result files: `eval/retrieval/results/2026-09-18-qwen3-embedding-0.6b-strip-reminder-text.json` and `eval/retrieval/results/2026-09-18-qwen3-embedding-0.6b-verbalize-symbols.json`. The frozen tuple and its prefix set `9D84B9513202418B` do not change. The two other compositions stay selectable through `Embedding:Composition` for regression comparisons, as the nomic fallback does for the model slot. A non-default composition joins the prefix-set hash, so the vector spaces never mix.
