# Postgres + pgvector as the single store, with a structural legality boundary

The corpus is a small curated lookup graph (~33k cards, ~3k rules, 1–2-hop relationships), so despite its graph shape we use one Postgres container (`pgvector/pgvector:pg18`) as the only store — corpus, index, collection, and simulation artifacts in one database, relationships as plain edge tables. A graph database would add a second data model and fragment the "no query path returns an illegal candidate" property across two schemas; if graph analytics ever reach the roadmap, PG19's SQL/PGQ adds pattern matching over the same tables at zero migration cost.

Structured filters and pgvector KNN compose in a single SQL statement (pgvector 0.8 iterative index scans), never as app-side post-filtering. Legality is enforced structurally: ingest derives a legality table keyed (card, role, banlist version), candidates are exposed only through a `legal_candidates(banlist_version, role)` set-returning function that the data-access layer composes every index query from, and a property test fuzzes index endpoints asserting zero illegal candidates. Callers supply a banlist version (default latest, pinnable).

Data access is EF Core 10 + Npgsql + `Pgvector.EntityFrameworkCore`; migrations own the DDL, with parameterized raw SQL for hybrid search and the legality function.

Amendment (2026-08-27, staple cut): derived-state phases add one non-query carve-out. Each derived table has a migration-owned `_staging` twin; a phase rebuilds staging with raw TRUNCATE / INSERT…SELECT and publishes through `Ingest/DerivedStateSwap.cs` — a transaction of `ALTER … RENAME` exchanges built from compile-time identifiers. The exchange restores the migration-declared names, so the schema at rest stays exactly what migrations own.

Amendment (2026-08-28, legality boundary): the function is `legal_candidates(banlist_version date, role text, color_identity_mask integer default null) returns setof card` — a STABLE single-SELECT SQL function, so Postgres inlines it and plans the caller's predicates and KNN ordering together with its one seek on the legality index. `ArchiveDbContext.LegalCandidates` is its only call site; `Api/CandidateQuery` resolves every candidate query's shared inputs into it. Index endpoints are the POST routes whose body derives from `CandidateQueryRequest`, and the property harness discovers them from the route table, so every later endpoint is fuzzed as it lands.

Amendment (2026-08-28, collection scope): the function gains a fourth parameter, `collection_scope boolean default false`, keeping only cards with a `collection_card` row — ownership is enforced at the same boundary as legality, never app-side. Scoped availability composes into the same statement through `available_copies(copy_limit, oracle_id)` = min(copy limit, owned quantity), mapped as an EF function (`ArchiveDbContext.AvailableCopies`). The property harness fuzzes `collection_scope` on every index endpoint and a sibling property test forces it on: no scoped query path returns an unowned candidate.

Amendment (2026-08-29, embedding storage): the three embeddable tables — `card_face_document`, `cr_rule_chunk`, `cr_glossary_chunk` — each carry a nullable `embedding vector(1024)` column with an HNSW cosine-distance index (`vector_cosine_ops`, the `<=>` operator every KNN orders by). 1024 is the primary model's width (`qwen3-embedding:0.6b`); the `nomic-embed-text` fallback (768) is zero-padded to that width rather than migrated, decided in ADR 0007. The `embedding_state` singleton records (model tag, dimensions, prefix-set version) the stored vectors were produced under; `Embedding/EmbeddingStateGate` reports semantic queries disabled on any disagreement until a re-embed rewrites the record, so vector spaces never mix. All embedding goes through `Embedding/OllamaEmbedder` (OllamaSharp over the stock ollama container, which the service provisions at startup): it prepends the per-model prefixes itself, since Ollama applies none, and sends `truncate: false` so an over-long input is refused, never silently cut.
