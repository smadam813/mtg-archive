# Abstracted disruption with no response window

Tier 3 layers disruption onto the goldfish engine as a caller-supplied deterministic schedule: a disruption profile of one-shot events from a closed vocabulary (`counterspell`, `targeted_removal`, `board_wipe`) that unlock on their scheduled turn and fire by a hardcoded adversarial-toward-the-goal targeting rule (most expensive qualifying goal card, deterministic name tie-break). Stochastic arrival and a swappable opponent-policy seam were rejected: a deterministic schedule keeps the result attributable to the deck rather than to disruption variance, and adversarial targeting is what makes the disrupted number an honest floor.

The goldfish turn casts instants at sorcery speed, and tier 3 keeps that: there is no response window. Disruption resolves unconditionally, the pilot stays the unchanged greedy — blind to the profile, so tier 3 varies the environment and nothing else — and the deck's own counterspells and protection contribute nothing. Resilience is measured purely as rebuild speed: redundant copies, recursion, recasting the commander through its tax. Reopening the window would drag in priority, a mini-stack, and a new choice point — the single biggest step toward the out-of-scope tier-4 engine — while the vision justifies tier 3 as "cheap once tier 2 exists." The omission is declared in the envelope's tier-3 assumptions block rather than silently absorbed.

Two consequences bind the rest of the engine. `on_battlefield(card, by_turn)` is point-in-time — the card must be on the battlefield at the end of turn `by_turn` — because achieved-the-moment-it-enters semantics would let end-of-turn removal leave the goal formally met and collapse the resilience delta (tier-2 numbers are unchanged; nothing there removes permanents). And a tier-3 run is inherently paired: the same seeds run with and without the profile, so the reported resilience delta carries no sampling noise between the arms; `runs` means pairs, and the caller pays the 2× execution cost.

**Note (ADR 0011):** tier 4 is now in scope, so the reasoning above that treats the tier-4 engine as out of scope no longer holds. This decision stands as the tier-3 design, and it runs on XMage.

**Note (2026-10-11, [ADR 0013](0013-interactive-disruption.md)):** the response window exists only in interactive disruption, the first tier-4 question. Abstracted disruption keeps this design and stays the default. The rejection of an opponent-policy seam stands: the scripted opponent acts only through the profile and has no policy name.
